1. גיבוי לפני שינוי

צור גיבוי במק וגם באתר. הכפתור מגבה את הסביבה שמופיעה בראש העמוד ומוריד ZIP עם מסד SQLite והתמונות שהועלו. הגיבוי כולל משתמשים ומידע פרטי. להפסקה מתואמת של שינויים במסד ובתמונות, בקש מהמשתמשים להימנע מעריכה בזמן הגיבוי.

{% csrf_token %}

חלופה במסוף: גיבוי מסד בלבד (בלי תמונות), נשמר בתיקיית backups בסביבה שבה הופעלה הפקודה:

python manage.py backup_database
בפרסום הראשון: הגיבוי בשרת הישן, לפני שהכלי זמין בו

ב־Render פתח SeaSlugs → Shell. הפקודה הבאה יוצרת גיבוי מסד בדיסק הקבוע, בלי לשנות את המקור. הורד אותו באמצעות scp לפי פרטי Connect → SSH ב־Render. הורד גם את תיקיית media אם קיימת.

python -c "import sqlite3,datetime; p='/var/data/pre-release-'+datetime.datetime.now().strftime('%Y%m%d-%H%M%S')+'.sqlite3'; a=sqlite3.connect('/var/data/db.sqlite3'); b=sqlite3.connect(p); a.backup(b); b.close(); a.close(); print(p)"

לאחר עדכון הקוד יהיה אפשר להוריד גיבוי מהכפתור גם באתר.

2. בדיקת הגרסה המקומית

העתק למסוף במק. המשך רק אם הבדיקות הסתיימו בהצלחה.

cd /Users/boazliebes/SeaSlugs
.venv/bin/python manage.py check
.venv/bin/python manage.py test observations
.venv/bin/python manage.py makemigrations --check --dry-run

3. הכנת הנתונים להעברה

פתח העברת טבלאות בסביבת המקור, וייצא את הטבלאות הדרושות. אפשר להעביר מהמק לאתר או מהאתר למק. סדר הייבוא ביעד:

    {% for key,label in tables %}
  1. {{ label }} {{ key }}
    2. {% endfor %}

ב־Samples המשתמש משויך לפי שם משתמש. המשתמש חייב כבר להתקיים ביעד; סיסמאות ותפקידים אינם מועתקים. ההעברה אינה מוחקת רשומות שאינן בקובץ, ואינה מעבירה רשומות מסומנות כמחוקות. תמונות YouTube נתמכות; העברה עם קובצי תמונה מקומיים תיעצר ותדרוש טיפול במדיה.

4. פרסום הקוד

הפעל את הסקריפט במק. הוא מציג את השינויים ומבקש אישור לפני העלאה ל־GitHub.

open "/Users/boazliebes/SeaSlugs/Publish SeaSlugs.command"

ב־Render בחר SeaSlugs → Manual Deploy → Deploy latest commit אם לא הופעלה פריסה אוטומטית. בפריסה שמשנה את מבנה הנתונים יש לתאם חלון תחזוקה; אחרי שהקוד הופך ל־Live ועד להשלמת הייבוא, ייתכן שהגלריה תהיה ריקה.

5. השוואה וייבוא ביעד

פתח את כלי העברת הטבלאות בסביבת היעד. העלה כל קובץ לפי הסדר, קרא את ההבדלים ואשר רק את העדכונים הרצויים. לפני כל ייבוא נוצר גיבוי אוטומטי. הרצה חוזרת עם אותם נתונים לא אמורה ליצור כפילויות.

6. בדיקה לאחר פרסום

בדוק את הגלריה באתר, מספר הסרטונים, כניסה ויציאה, והתצפיות של משתמש רגיל ושל מנהל. שמור את מזהה הגרסה המוצג ב־Render ליד קובץ הגיבוי.

שחזור במקרה תקלה

אל תחליף קובץ SQLite בזמן שהאתר פועל. שחזור מלא דורש עצירת כל תהליכי האתר, בחירת קוד תואם לגיבוי והחזרת המסד והמדיה יחד. הכלי הזה אינו מבצע החלפה מלאה אוטומטית. תיקוני תוכן נקודתיים אפשר לבצע באמצעות ייצוא והשוואת טבלאות.
